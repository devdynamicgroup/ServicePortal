# M8.6 — Notification Identity Read Validation Report Design

**Status:** Architecture design (not implemented)  
**Purpose:** Observe Case vs Customer LINE destination during shadow / early primary notify reads.

---

## Report metadata

| Field | Description |
|-------|-------------|
| `runId` / `windowStart` / `windowEnd` | Observation window |
| `mode` | `case_only` \| `shadow` \| `primary` |
| `flagsSnapshot` | ENABLED, DUAL_WRITE, READ_LINE, READ_NOTIFY, READ_NOTIFY_SHADOW |

---

## Counters

| Metric | Meaning |
|--------|---------|
| `notifyResolves` | Total destination resolutions for send attempts |
| `customerHits` | Customer found with non-empty LINE used or compared |
| `customerMisses` | No Customer for Case `customer.id` / missing link |
| `customerNoLine` | Customer found but empty `lineUserId` |
| `caseFallbacks` | Push used Case LINE due to miss/empty/error/mismatch |
| `casePrimaryHits` | Push used Case path (case_only or shadow authoritative) |
| `mismatches` | Customer LINE ≠ Case LINE (both non-empty) |
| `missingLinks` | Case has no `customer.id` while Case has LINE (or inverse for forensics) |
| `errors` | Customer path exceptions (fallback engaged) |
| `skippedNoLine` | Neither path yielded a LINE (existing skip) |

---

## Detail samples (PII-safe)

Log truncated/hashed LINE ids only in shared logs.

| Section | Content |
|---------|---------|
| `mismatches[]` | `caseId` / `customerId`, both LINE redacted |
| `missingLinks[]` | `caseId`, reason |
| `errors[]` | `caseId`, error code |

---

## Acceptance gates (suggested)

| Gate | Shadow | Primary |
|------|--------|---------|
| Wrong-recipient incidents | 0 | 0 |
| Unexplained mismatch rate | &lt; 1% | &lt; 0.5% |
| Fallback available | Yes | Yes |
| Message payload unchanged | Required | Required |
