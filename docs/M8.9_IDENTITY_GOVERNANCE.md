# M8.9 — Identity Governance (Steady State)

**Status:** Active governance policy  
**Runtime impact:** None — documentation only  
**Related:** `docs/M8.9_GOVERNANCE_STEADY_STATE.md` · `docs/M8.9_OPERATIONS_CADENCE.md` · `docs/M8.9_IDENTITY_INCIDENT_RUNBOOK.md`

---

## Target architecture

```text
Case  = operational aggregate root
        + denormalized LINE User ID (permanent fallback)
        + Customer ID / Customer Page ID (link)

Customer = identity projection only
```

---

## Ownership boundaries

### Case owns (operational SSOT)

| Domain | Notes |
|--------|--------|
| Booking | Case page / booking fields |
| Workflow | Case workflow status & timestamps |
| Offer | Case offer / campaign properties |
| Feedback | Feedback linked to Case |
| Report | Tokens, score, report URL on Case |
| Notification **state** | `notificationStatus`, `resultSentAt`, message ids, errors |

Case never cedes these to Customer.

### Customer owns (identity domain)

| Domain | Notes |
|--------|--------|
| Canonical identity | Display name, phone, email, address |
| LINE identity projection | `lineUserId`, display name, linked timestamps |
| Customer lifecycle status | active / merged / anonymized / … |
| Consent / locale (identity metadata) | As modeled on Customers DB |

Customer never owns Booking, Workflow, Offer, Feedback, Report, or Notification **state**.

### Link

Case → Customer via `customerId` / `customerPageId` (additive).  
Logical identity SSOT is Customer; Case keeps denormalized LINE for fallback and safety.

## RACI

| Activity | Operator | Reviewer | On-call | Identity steward |
|----------|----------|----------|---------|------------------|
| Reconcile scan / archive | **R** | C | I | C |
| Allow-listed dry-run repair | **R** | C | I | C |
| Allow-listed write repair | **R** | **A** | I | C |
| M8.8 phase go/no-go | R | **A** | C | C |
| Flag enable / disable (env) | R | **A** | **A** (rollback) | C |
| Manual Customer merge | C | C | I | **A/R** |
| Ticket `line_diverge` | R | C | I | **A** |
| Emergency flag rollback | C | I | **R/A** | I |

R = Responsible, A = Accountable, C = Consulted, I = Informed

---

## Permanent rules

1. **Case LINE User ID retained indefinitely** — fallback for OA history, notify destination, and Case-wins-on-diverge.  
2. **Exact matching only** — LINE → phone → email (normalized).  
3. **No fuzzy matching** and **no name-based auto-match / auto-merge**.  
4. **No automatic merge** — M8.4 manual execute only when explicitly enabled.  
5. **No destructive repair** — `line_diverge` is report/ticket only; never overwrite Case LINE from Customer on diverge.  
6. **Human-controlled flags** — M8.8 runbook / checklist; no application auto-promote.  
7. **Notification lifecycle remains Case-owned** — forever under this ADR.  
8. **Dual-write stays ON** in steady state after enablement (prevents new drift).  

---

## Matching & repair (steady state)

| Action | Policy |
|--------|--------|
| Identity match | Exact keys only |
| `link_missing` / fill empty LINE | Allow-listed M8.7 repair after dry-run |
| `line_diverge` | Steward decision / M8.4 — never auto |
| Soft phone/email conflict | Report; steward backlog |

---

## Explicit non-goals (require new ADR / M9+)

- Remove Case LINE fields  
- Move Offer / Workflow / Feedback / Report / Notification state under Customer  
- Auto-merge or fuzzy match  
- App-driven flag promotion

## Flag ownership

Production `CUSTOMER_DOMAIN_*` values are **ops-owned** environment configuration.  
Repo defaults remain `false`. Enablement follows `docs/M8.8_PHASE_RUNBOOK.md`.
