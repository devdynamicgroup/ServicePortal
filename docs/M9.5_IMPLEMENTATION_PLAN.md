## Doc content outline (for implement)

### Steady-state handbook

- Ownership table (Case / Customer / Care)  
- End-to-end loop after launch  
- Weekly / monthly / per-deploy / per-CDR workflow  
- Pointers to M9.1–M9.4 artifacts (compose, don’t duplicate entire runbooks)  
- Explicit: M9.5 does not enable SEND  

### Metrics ownership

| Class | Metrics | Owner | Escalate to |
|-------|---------|-------|-------------|
| Delivery | sent, failed, skipped, duplicates | Operator | On-call on fail-pause / spikes |
| Outcome | response, rebook, opt-out, complaints | Operator + Reviewer | Steward for consent; On-call for complaints |
| Governance | CDR history, policy changes, approvals | Operator / Reviewer | On-call for incident CDRs |

### CDR operations

- Lifecycle: draft → approved → applied → reverted  
- Weekly classification → CDR when `propose_change`  
- Monthly open-CDR review  
- Same-lever spacing (≥7 days) unless incident  
- Forbidden auto-create from scripts  

### Incident operations

| Class | First action |
|-------|--------------|
| Delivery failure / fail-pause | `SEND=false` |
| Wrong recipient | `SEND=false` |
| Consent bug | `SEND=false` + steward |
| Boundary / Case mutation suspicion | `SEND=false` + `ENABLED=false` |
| Eval / cron chaos | `ENABLED=false` if needed |

Rollback remains flag-only. Non-actions: no Case rewrite, no Customer rollback, no audit deletion.

### Optional steady-state script

```text
Inputs: flags + latest.json + latest-outcome-report.json (if present)
Output: suggested phase, governance reminders, fail-pause hint, doc links
Never: set env, send LINE, apply policy, create CDRs, enable SEND
```
