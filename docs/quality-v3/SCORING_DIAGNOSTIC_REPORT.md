## Part 3 — Country Benchmark Plateau Diagnostic

**Source verified live** from `src/js/score/benchmark/{thailand,japan,who,eu,usEpa}/limits.js`
and `score.js` (not from prior documentation).

### 3a. Confirmed: limit shapes are not uniform across engines

Contrary to treating all 5 country engines as the same "PASS = flat 100"
shape, the actual `limits.js` files use **at least 4 different limit
structures** depending on parameter:

| Shape | Used by | Behavior |
|---|---|---|
| `{min, max}` (symmetric band) | pH, ORP, Chlorine (most engines) | Verified flat-100 across the entire probed range between min and max |
| `{passMax, softEnd}` | Thailand TDS/Turbidity | Flat-100 up to `passMax`, then ramps down to `softEnd` |
| `{ideal, fair, poor}` graded bands | **WHO** TDS/Turbidity, Chlorine | **Genuinely graded within what other engines would treat as one PASS window** — see 3b |
| `{displayMax}` / `{smcl}` / `{ideal, steepEnd}` / single-sided `{min}` or `{max}` | Japan/EU/EPA TDS, Turbidity, DO | Not fully probed by this pass's boundary script (unrecognized shape by the generic probe) — flagged as incomplete, not assumed flat |

### 3b. WHO already implements internal grading — this is not a uniform defect

`src/js/score/benchmark/who/score.js` (lines 20–29) computes TDS and
Turbidity as **linear ramps through three tiers** (`ideal → fair → poor`),
not a flat pass value:

```
TDS:      ≤300 → 100flat, 300–600 → ramps 100→80, 600–1000 → ramps 80→50, beyond → declines further
Turbidity: ≤1 → 100flat, 1–5 → ramps 100→70, 5–10 → ramps 70→30, beyond → declines further
```

This directly contradicts treating "PASS region → flat 100" as a
description of every engine. **WHO's TDS/Turbidity already have a
preferred-range structure**; the open question for WHO specifically is
whether `ideal:300 / fair:600 / poor:1000` (etc.) has any cited source —
that is a provenance question (Part 5), not a "needs graded scoring"
question, because it already has one.

### 3c. Confirmed flat-100 (verified by direct probe) for `{min,max}`-shaped parameters

All values probed with the other 5 parameters held at the Quality V3 ideal

## Part 4 — Aggregation Diagnostic

**EXPERIMENTAL DIAGNOSTIC — NOT A PROPOSED MODEL.** Computed from Case A/B's
existing, unmodified parameter grades. No winner is selected; no aggregation
is recommended.

| Aggregation | Case A | Case B | A−B gap |
|---|---:|---:|---:|
| Arithmetic mean (current production formula) | 91.64 → **92** | 72.86 → **73** | 18.78 |
| Geometric mean | 91.17 | 72.11 | 19.06 |
| Harmonic mean | 90.65 | 71.32 | 19.33 |
| 90/10 blend toward minimum | 89.96 | 71.09 | 18.87 |
| 80/20 blend toward minimum | 88.28 | 69.33 | 18.95 |
| 70/30 blend toward minimum | 86.59 | 67.56 | 19.03 |
| Minimum parameter only | 74.80 | 55.20 | 19.60 |

**Interpretation (observation, not a decision):** across every aggregation
method tried, the **A–B gap stays within a narrow 18.78–19.60 point band**.
Changing the aggregation formula moves the *absolute* score level
(arithmetic 92 vs. minimum 74.8 for Case A — an 17-point swing) but barely
moves how well the model *discriminates* Case A from Case B. This suggests
aggregation choice is primarily an absolute-calibration question ("what
number should a profile like Case A produce"), not a discrimination
question ("can the model tell Case A and Case B apart") — the model already
separates them by roughly 19 points under every formula tested. This
narrows, but does not resolve, the open aggregation decision in
`UNRESOLVED_DECISIONS.md` §1.

## Part 8 — Final Report

### A. What is proven (verified directly against live code this pass)

- Quality V3's math is internally consistent: `Math.round(sum(6 param grades)/6)`, single rounding point, confirmed by direct probe.
- Five of six Quality parameter curves (pH, TDS, Turbidity, ORP, DO) are smooth and monotonic across a wide probed range with no undocumented discontinuities.
- **The Quality chlorine curve has one genuine cliff**: +18 points for a 0.01 mg/L change at the 0.08 mg/L branch boundary.
- **The EU country-benchmark chlorine curve has a genuine cliff of its own**: ±35 points at its band edges (0.1 and 0.5 mg/L) — newly found, not previously documented.
- ORP's 400 mV center and 200–600 mV band are reused byte-for-byte across all 5 country engines — reconfirmed independently this pass.
- WHO's country engine already implements graded (non-flat) scoring for TDS and Turbidity within what other engines treat as a single flat PASS band — the "PASS region = flat 100" pattern is **not universal**, it varies by engine and by parameter.
- Case A (92) vs. Case B (73) separates by ~19 points under every aggregation formula tested (arithmetic, geometric, harmonic, three minimum-weighted blends) — aggregation choice affects absolute score level far more than it affects discrimination between these two cases.
- No parameter center (pH 7.2, TDS 80, Turbidity 0.08, ORP 400, Chlorine 0.30, DO 8.0) has a linked external regulatory/scientific source anywhere in the repository — only prose rationale.

### B. What is uncertain

- Whether any of the 6 Quality centers, or their breakpoints/slopes, represent the "right" values — no independent, outcome-labelled evidence exists to judge this (unchanged from `MODEL_PROVENANCE.md`).
- Whether WHO's `ideal/fair/poor` band values (300/600/1000 for TDS, etc.) have any external source — not checked by this pass.
- Full boundary behavior of Japan/EU/EPA TDS, Turbidity, and DO — several limit shapes (`displayMax`, `steepEnd`, single-sided `min`) were not covered by this pass's generic boundary probe and would need a shape-specific probe to characterize fully.
- Which aggregation model (if any) should replace the current arithmetic mean — Part 4 narrows the question but does not answer it, and selecting one requires a prior product decision on what Quality V3 is supposed to represent (per `UNRESOLVED_DECISIONS.md` §1).

### C. What should NOT be changed yet

- `computeQualityScoreV2.js`, any `src/js/score/benchmark/**` engine, `measurementValidator.js`, `src/js/flows/score.js` — untouched, and per this diagnostic's hard rules, not to be changed based on this report alone.
- Case 1328 / Case A / Case B values — used exactly as registered, never modified.
- Aggregation formula, curve centers, curve breakpoints, country limits, country grading structure — all remain frozen pending explicit product/domain sign-off per `DECISION_MATRIX.md`.

### D. What information is needed before recalibration

Per `CALIBRATION_WORKFLOW.md` §6 and `EVIDENCE_ACQUISITION_PROTOCOL.md` §5
(unchanged by this pass — restated here for completeness):

- **Real field samples** spanning each parameter's realistic range (pH 6.0–9.0+, TDS 50–1000+, Turbidity 0–5+ NTU, full ORP operational range, Chlorine across the 0.1/0.22/1.0 branch boundaries, DO low→normal→high), submitted via `EVIDENCE_ACQUISITION_PROTOCOL.md`'s intake process.
- **Outcome-labelled samples** — at least some real readings with a lab result, technician assessment, customer assessment, or regulatory status attached (currently zero exist in the registry).
- **Independent validation and holdout samples** — frozen before any recalibration attempt, never used to tune.
- **A prior product decision** on what Quality V3 is meant to represent (closeness-to-ideal index vs. safety-adjacent signal) before any aggregation change is even scoped, per `UNRESOLVED_DECISIONS.md` §1.
- **Regulatory/scientific sourcing** (or an explicit decision to proceed without it, recorded as such) for each of the 6 curve centers, and separately for any within-PASS country grading band, before touching any of them.
- Specifically for the two cliffs found in this pass (Quality chlorine 0.08 branch, EU chlorine 0.1/0.5 boundaries): either a documented rationale for why a step function is intentional there, or evidence-backed replacement with a ramp — both require sign-off, neither is implemented by this report.
