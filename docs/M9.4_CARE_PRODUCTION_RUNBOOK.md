## Locked sequence

```text
Phase 0  CARE OFF
Phase 1  CARE_LIFECYCLE_ENABLED=true   (SEND still false)
Phase 2  Dry-run verification
Checkpoint A  Production readiness sign-off
Phase 3  CARE_LIFECYCLE_SEND=true
           → --limit=10 → observe ≥24h → Checkpoint B
           → --limit=50 → observe ≥48h (prefer 72h) → Checkpoint C
           → uncapped
Phase 4  Steady state
```

Staging: complete Phase 1–2 there first **if staging exists**. Otherwise full prod dry-run gates + Reviewer/On-call (no shortcut).

## Phase 2 — Dry-run verification

| | |
|--|--|
| **Requires** | Phase 1 |

| **Fail** | Do not set SEND |

## Checkpoint A — before first SEND

Owners: **Operator + Reviewer + On-call**  
Use: `docs/M9.4_CARE_GO_NO_GO_CHECKLIST.md` Checkpoint A.

## Phase 3 — SEND ladder

| | |
|--|--|
| **Requires** | Checkpoint A GO |
| **Set (human)** | `CARE_LIFECYCLE_SEND=true` (ENABLED stays true) |
| **Detail** | `docs/M9.4_CARE_FIRST_SEND_PLAN.md` |

### Step 3a — limit 10

```bash
node scripts/run-care-lifecycle.js send --event=reinspection_6mo --mode=write --limit=10
```

Observe ≥ **24h**: Care Audit sent/failed; complaints; pattern scanner; fail-pause rule.

### Checkpoint B — before limit 50

Owners: **Operator + Reviewer** (On-call ack if incident since 3a).

### Step 3b — limit 50

```bash
node scripts/run-care-lifecycle.js send --event=reinspection_6mo --mode=write --limit=50
```

Observe ≥ **48h** (prefer **72h** if uncertain).

### Checkpoint C — before uncapped

Owners: **Operator + Reviewer**.

### Step 3c — uncapped / cron

Document single runner. Steady send only after Checkpoint C GO.

## Monitoring (all Phase 3+)

| Area | Action |
|------|--------|
| Delivery | Review `latest.json` sent/failed/skipped |
| Fail-pause | If `failed/(sent+failed) ≥ 0.20` and n≥5 → **pause SEND** (rollback card) |
| Skips | Mix must stay explainable |
| Duplicates | Idempotency / `already_sent`; never delete index mid-incident |
| Complaints / wrong recipient | Immediate SEND=false |
| Outcomes | Weekly `run-care-outcome-report.js` + M9.3 classification (flags may stay OFF) |

---

## Phase 4 — Steady state

Follow `docs/M9.1_OPERATIONS_CADENCE.md` + **`docs/M9.5_CARE_STEADY_STATE_HANDBOOK.md`** (ownership, CDR ops, incidents, metrics).

- Weekly review of skips / sent / failed + outcomes  
- Monthly volume + consent/copy check + CDR follow-ups  
- Policy changes → CDR (`docs/M9.5_CARE_CDR_OPERATIONS.md`)  
- Incident: `docs/M9.5_CARE_INCIDENT_OPERATIONS.md` / rollback cards  
- SEND remains reversible; M9.5 never enables SEND  

Ownership remains: Case = ops SSOT; Customer = identity; Care = eligibility + Care Audit + outcomes + CDRs.
