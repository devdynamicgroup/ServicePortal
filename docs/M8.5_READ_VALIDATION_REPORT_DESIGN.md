# M8.5 — Read Validation Report Design

**Status:** Architecture design (not implemented)  
**Purpose:** Observe Case vs Customer LINE resolution during shadow / early primary read.

---

## Report metadata

| Field | Description |
|-------|-------------|
| `runId` / `windowStart` / `windowEnd` | Observation window |
| `mode` | `shadow` \| `primary` |
| `flagsSnapshot` | ENABLED, DUAL_WRITE, READ_LINE, READ_NOTIFY |

---

## Counters

| Metric | Meaning |
|--------|---------|
| `lineLookups` | Total LINE history/latest resolutions |
| `customerHits` | Customer found by exact LINE User ID |
| `customerMisses` | No Customer for LINE User ID |
| `caseFallbackHits` | Response used Case LINE query fallback |
| `casePrimaryHits` | Response used Case path (shadow authoritative or flag off) |
| `mismatches` | Customer-path case set ≠ Case-path case set (by notionId) |
| `missingLinks` | Customer found but zero Cases with Customer ID link |
| `conflicts` | &gt;1 Customer with same LINE (should be rare post-M8.4) |
| `errors` | Customer path exceptions (fallback engaged) |

---

## Detail samples (PII-safe)

Log `lineUserId` hashed or truncated in shared logs; keep full ids in secured ops reports only.

| Section | Content |
|---------|---------|
| `mismatches[]` | caseNotionIds onlyInCase / onlyInCustomer |
| `missingLinks[]` | customerId, lineUserId |
| `conflicts[]` | customerIds sharing LINE |

---

## Acceptance gates (suggested)

| Gate | Shadow | Primary |
|------|--------|---------|
| Flags READ_NOTIFY off | Required | Required |
| `conflicts` | 0 unexplained | 0 |
| `mismatchRate` | &lt; 1% | &lt; 0.5% after fallback |
| Fallback available | Yes | Yes |

---
