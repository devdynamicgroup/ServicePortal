# M9.3 — Care Decision Records (CDR)

**Status:** Active (governance)  
**Storage:** Markdown docs only — **never** inside CareAuditEvent / `events.jsonl`  
**Related:** `docs/M9.3_POLICY_REVIEW_RUNBOOK.md` · `docs/M9.3_EFFECTIVENESS_GOVERNANCE.md` · `docs/M9.5_CARE_CDR_OPERATIONS.md` (steady-state cadence)

---

## Purpose

A **Care Decision Record** is the human audit trail for Care policy learning.

```text
Outcome report (M9.2)  →  Human review  →  CDR  →  Approved change
```

Care Audit remains the immutable history of **what was planned/sent**.  
CDR is the history of **what we decided to change**.

---

## Separation rules (locked)

| Store | Contains | Mutable? |
|-------|----------|----------|
| CareAuditEvent (`tmp/care-lifecycle/events.jsonl`) | Delivery / skip / outcome fields | **Immutable** historical rows |
| CDR (`docs/care-decisions/CDR-*.md` or this schema) | Decisions + approvals | New files / status updates only |

- Never append a CDR into `events.jsonl`  
- Never rewrite past audit rows to “apply learning”  
- Never auto-create CDRs from scripts  

---

## When a CDR is required

| Change type | Examples |
|-------------|---------|
| Template | Copy text, `templateVersion` bump |
| Timing | `CARE_REINSPECTION_DAYS`, documented response/rebook windows |
| Throttle | Cron frequency, default `--limit=` ladder guidance |
| Eligibility | Eligibility constants, skip-rule code thresholds |

## When a CDR is not required

| Activity | Notes |
|----------|--------|
| Report generation | `run-care-outcome-report.js` |
| Audit / report viewing | Read-only |
| Incident rollback | `docs/M9.1_ROLLBACK_CARD.md` first; optional post-incident CDR |
| Fixture / governance tests | Local only |

## Schema (minimum fields)

| Field | Type / values | Purpose |
|-------|---------------|---------|
| `id` | `CDR-YYYYMMDD-##` | Stable id |
| `date` | ISO date | When drafted |
| `author` | string | Who drafted |
| `reviewer` | string | Who approved (required before `applied`) |
| `metricSnapshot` | object/text | sent, failed, skip mix, rebookRate, sample size, report path |
| `finding` | text | What looks wrong or improvable |
| `decision` | see below | Chosen action class |
| `changeDetail` | text | Before → after (env/key/version) |
| `rollback` | text | How to undo |
| `followUp` | text | Next dry-run / success criteria / due date |
| `status` | see below | Lifecycle |

### `decision` values

`no_change` | `template` | `timing` | `throttle` | `eligibility` | `pause_send`

### `status` values

`draft` → `approved` → `applied` → (`reverted` if rolled back)

**Rule:** Do not set `applied` without a named `reviewer` and `approved` status first.

## Example B — timing change (requires approval before apply)

```markdown
# CDR-20260804-02

| Field | Value |
|-------|-------|
| date | 2026-08-04 |
| author | operator |
| reviewer | reviewer |
| status | approved |

## metricSnapshot
- dry_run eligible volume stable
- steward sample: anchors correct; care too early vs service date

## finding
Reinspection reminder feels early for some completed jobs.

## decision
`timing`

## changeDetail
Before: CARE_REINSPECTION_DAYS=182
After: CARE_REINSPECTION_DAYS=200

## rollback
Set CARE_REINSPECTION_DAYS=182

## followUp
Dry-run scan within 7 days; spot-check ≥20 rows; do not enable SEND via this CDR.
```
