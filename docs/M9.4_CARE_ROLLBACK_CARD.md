# M9.4 — Care Rollback Card (Production)

**Emergency use.** Stop Care Lifecycle production sends via environment flags only.  
Companion to `docs/M9.1_ROLLBACK_CARD.md` (same flag order; this card adds ladder / first-send context).

**Do not** rewrite Case notification state, delete Customers, clear Care Audit, or delete the idempotency index mid-incident.

Related: `docs/M9.4_CARE_PRODUCTION_RUNBOOK.md` · `docs/M9.4_CARE_FIRST_SEND_PLAN.md`

---

## Immediate order (flag-only)

```text
1. CARE_LIFECYCLE_SEND=false
2. CARE_LIFECYCLE_ENABLED=false    # if evaluation / cron must stop
```

Redeploy / restart as required by the host.

---

## When to roll back

| Symptom | Minimum action |
|---------|----------------|
| Wrong recipient / care spam complaint | Step 1 (SEND off) |
| Fail-pause: failed/(sent+failed) ≥20% with n≥5 | Step 1; investigate Care Audit / LINE |
| Failed send spike | Step 1 |
| Dry-run / scan instability (pre-SEND or ENABLED-only) | Step 2 |
| Suspected Case notification mutation | Steps 1–2; escalate (should be impossible) |
| Full abort during ladder or steady state | Steps 1–2 |

---

## During limit ladder

| Step in progress | Rollback |
|------------------|----------|
| After limit 10 / before 50 | SEND off; do **not** expand to 50 |
| After limit 50 / before uncapped | SEND off; do **not** uncapped |
| Uncapped / cron | SEND off; disable cron if needed; optionally ENABLED off |

Re-entry only via new go/no-go (return to dry-run / Checkpoint A as Reviewer requires).

---

## After rollback — verify

```bash
node scripts/check-care-rollout-gates.js
node scripts/check-care-production-readiness.js
```

- [ ] CARE flags match intended safe state  
- [ ] Case result-send still works  
- [ ] LINE OA history/latest still works  
- [ ] Care Audit reports retained under `tmp/care-lifecycle/`  
- [ ] Idempotency index retained  

Optional: post-incident CDR (`docs/M9.3_CARE_DECISION_RECORDS.md`) after stability — never a substitute for immediate flag rollback.

---

## Explicit non-actions

- Do **not** delete Care Audit files or idempotency index as “cleanup” during incident  
- Do **not** modify Case `notificationStatus` / `resultSentAt` to “undo” care  
- Do **not** enable Customer Domain flags as a fix  
- Do **not** fuzzy-merge or mass-unlink  
- Do **not** auto-re-enable SEND from scripts  

Result-send and Customer Domain flags are **out of scope** unless a separate M8.8 incident applies.

---

## Ownership

| Role | Duty |
|------|------|

| Operator | Preserve audits/reports; stop cron |
| Reviewer | Approve any re-entry to SEND |
