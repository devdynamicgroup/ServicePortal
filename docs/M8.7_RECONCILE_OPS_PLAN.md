# M8.7 — Identity Reconciliation & Operations Plan

**Status:** Implemented (offline tooling; flags unchanged / default OFF)  
**Out of scope:** Auto-merge; removing Case LINE fields; runtime read/notify changes; HTTP mutation; enabling flags

---

## Goal

Make Customer identity **operable and auditable** before (and during) any production read rollout:

1. Detect Case ↔ Customer identity **drift** offline  
2. Expose **ops-safe** metrics and flag posture  
3. Provide **manual, dry-run-first** repair actions that are additive / reversible  
4. Document **rollout gates** for M8.5 / M8.6 flags without auto-enable  

M8.7 does **not** flip production to Customer-primary by itself.

---

## CLI

```bash
node scripts/run-customer-reconcile.js scan
node scripts/run-customer-reconcile.js repair --action=link_missing
node scripts/run-customer-reconcile.js repair --action=fill_case_line_from_customer --mode=write
node scripts/run-customer-reconcile.js status
node scripts/test-customer-reconcile.js
node scripts/dump-customer-line-read-metrics.js
node scripts/dump-customer-notify-read-metrics.js
```

Repair **default** is dry-run (`--mode=write` required to apply).

Allowed actions: `link_missing`, `fill_case_line_from_customer`, `fill_customer_line_from_case`.  
`line_diverge` is **report-only** (never auto-repaired).

Reports: `tmp/customer-reconcile/reconcile-<runId>.json` (+ `.summary.json`, `latest.summary.json`).
