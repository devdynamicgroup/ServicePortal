# M8.5 — LINE Read Migration Plan

**Status:** Architecture design (not implemented)  
**Flags:** `CUSTOMER_DOMAIN_READ_LINE` default **OFF**; requires `CUSTOMER_DOMAIN_ENABLED=true`  
**Out of scope:** `READ_NOTIFY`, Offer/Workflow ownership, API/Framer/Dashboard/webhook changes

---

## Scope

**In scope**

- LINE OA history / latest resolution path (`resolveLineCustomerCases` and callers)
- Customer lookup by **exact LINE User ID only**
- Case retrieval via Case `Customer ID` link
- Shadow dual-read validation mode
- Feature-flagged primary Customer read with Case fallback

**Out of scope**

- Notification send LINE resolution (`READ_NOTIFY` / M8.6)
- Removing Case `LINE User ID` denormalized fields
- Phone/email/name fallback for LINE lookup
- Public booking / offer / Dashboard contracts

---

## Runtime flow

### Flag OFF (default — no behavior change)

```text
lineUserId → findClientsByLineUserId(Cases) → sort/filter reports
```

### Shadow mode (`READ_LINE_SHADOW` or dual-read when ENABLED + shadow)

```text
lineUserId → Case path (authoritative response)
           → Customer path (async/side) → compare → metrics
```

### Primary Customer read (`ENABLED` + `READ_LINE`)

```text
lineUserId
  → findCustomerByLineUserId (exact)
  → if Customer found:
       → Cases WHERE Customer ID = customer.customerId
       → if Cases empty → fallback Case LINE query (optional policy)
  → if Customer not found / error:
       → fallback findClientsByLineUserId(Cases)
```

---

## Rollout stages

| Stage | Flags | Behavior |
|-------|-------|----------|
| A | all OFF | Today |
| B | ENABLED + dual-write ON (recommended before read) | Identity stays fresh |
| C | + READ_LINE shadow | Dual-read compare; Case still serves replies |
| D | READ_LINE primary | Customer→Cases serves replies; Case fallback on miss/error |
| E | Observe + lock | Acceptance metrics met; keep fallback until M8.7 cleanup |

---

## Validation

Use Read Validation Report (see `docs/M8.5_READ_VALIDATION_REPORT_DESIGN.md`).

Suggested acceptance (staging → prod shadow):

- Mismatch rate &lt; 1% over N lookups (e.g. 200+)
- Zero hard errors attributed to Customer path that degrade UX without fallback
- History latest score/URL parity for linked Customers

---

## Rollback

1. `CUSTOMER_DOMAIN_READ_LINE=false` → immediate Case-only reads  
2. No data rollback required  
3. Keep dual-write as-is
