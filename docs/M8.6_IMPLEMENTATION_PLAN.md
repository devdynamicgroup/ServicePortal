## Runtime design

### Mode selection

```text
ENABLED && READ_NOTIFY                         → primary
ENABLED && READ_NOTIFY_SHADOW && !READ_NOTIFY   → shadow
else                                           → case_only
```

Defaults: all false. No auto-enable.

### case_only

```text
destination = job.line.userId
no Customer Notion calls
```

Identical to today.

### shadow

```text
destination = job.line.userId          // always send via Case
side: Case.customer.id → findByCustomerId → customer.lineUserId
compare → metrics (match / mismatch / miss / no_line / error)
```

### primary

```text
caseLine = job.line.userId
if job.customer.id:
  customer = findByCustomerId (exact)
  if customer.lineUserId:
    if !caseLine → use customer
    if caseLine === customer.line → use customer
    if caseLine !== customer.line → mismatches++; use caseLine
  else → fallback caseLine
else → caseLine
on error → caseLine
```

Forbidden: phone / email / name / fuzzy / multi-Customer guess.

### Integration sketch (`executeSendCaseResult`)

```text
resolved = resolveNotifyLineDestination(job)
lineUserId = resolved.lineUserId
if !lineUserId → skipped (existing)
… status → sending …
sendJob = job with line.userId = lineUserId   // if differs
sendCaseResultNotification(sendJob, payload)  // unchanged message build
… sent/failed on Case (unchanged)
```

## Testing plan

| # | Scenario | Expect |
|---|----------|--------|
| 1 | Flags OFF | Case LINE; zero Customer calls |
| 2 | Primary: linked Customer, LINE equals Case | Destination Customer (same value); customerHits |
| 3 | Primary: Customer LINE, Case empty | Destination Customer |
| 4 | Primary: no customer.id | Case LINE; missingLinks or case-only path |
| 5 | Primary: Customer missing / no LINE | Case fallback |
| 6 | Primary: Case LINE ≠ Customer LINE | Case wins; mismatches++ |
| 7 | Shadow: mismatch | Send Case; mismatches++; Customer called |
| 8 | Customer path throws | Case fallback; errors++; send still works |
| 9 | READ_LINE on/off does not change notify mode | Isolation |
| 10 | Notification status transitions unchanged with mocks | sending→sent/failed still Case updates |

## Regression risks

| Risk | Mitigation |
|------|------------|
| Wrong recipient on LINE diverge | Case wins on mismatch |
| Double LINE source in send helper | Single resolve then patch `job.line.userId` for push only |
| Accidental OA/history coupling | Separate `notify-reader` vs `line-reader` |
| Latency on close | One `findByCustomerId`; fail-soft |
| Moving notify ownership | Status writes stay in workflow-service as today |
