# M9.1 — Care Phase Runbook

**Status:** Ops package live — CARE flags remain **OFF** until operators enable them  
**Never skip dry-run. Never jump to uncapped SEND without limit ladder.**

Related: `docs/M9.1_GO_NO_GO_CHECKLIST.md` · `docs/M9.1_ROLLBACK_CARD.md` · `docs/M9.1_OPERATIONS_CADENCE.md`

---

## Fixed sequence

```text
Phase 0  CARE OFF
Phase 1  CARE_LIFECYCLE_ENABLED=true   (SEND still false)
Phase 2  Dry-run observation (≥7 days + ≥3 scans)
Phase 3  CARE_LIFECYCLE_SEND=true
           → --limit=10 → --limit=50 → uncapped
Phase 4  Steady-state cadence
```

Low volume: dry-run may be **≥14 days** if needed for meaningful samples.

`CUSTOMER_DOMAIN_*` are independent — not required for Care.

---

## Shared commands

```bash
node scripts/test-care-lifecycle.js
node scripts/check-care-rollout-gates.js
node scripts/run-care-lifecycle.js scan --event=reinspection_6mo --mode=dry-run
node scripts/run-care-lifecycle.js send --event=reinspection_6mo --mode=write --limit=10
```

Archive reports under `tmp/care-lifecycle/` (`<runId>.json`, `latest.json`).

## Phase 0 — CARE OFF

| | |
|--|--|
| **Flags** | `CARE_LIFECYCLE_ENABLED=false`, `CARE_LIFECYCLE_SEND=false` |
| **Steps** | Run fixture tests; confirm gate script shows phase 0; baseline Case result-send healthy |
| **Success** | Tests green; no customer-facing care pushes |
| **Rollback** | N/A |

---

## Phase 1 — ENABLED (observe capability)

| | |
|--|--|
| **Set** | `CARE_LIFECYCLE_ENABLED=true` (`SEND` remains false) |
| **Steps** | Deploy/restart → `check-care-rollout-gates.js` → confirm SEND still false |
| **Success** | App healthy; dry-run scans allowed |
| **Rollback** | `CARE_LIFECYCLE_ENABLED=false` |
| **Hold** | Ready to start Phase 2 immediately once stable |

---

## Phase 2 — Dry-run observation

| | |
|--|--|
| **Requires** | Phase 1 |
| **Commands** | `scan --mode=dry-run` (repeat) |
| **Gates** | ≥ **3** successful scans over ≥ **7 days** (or ≥14 days low volume); spot-check ≥ **20** `dry_run` rows (or all if fewer); skip reasons explained; **0** unticketed false positives; Case `notificationStatus` unchanged in reports |
| **Success** | Signed go/no-go for SEND |
| **Rollback** | Keep SEND false; optionally disable ENABLED |
| **Fail → do not SEND** | Mass unexplained eligibility; wrong anchors; any Case notification mutation |

---

## Phase 3 — SEND (graduated)

| | |
|--|--|
| **Requires** | Phase 2 gates signed |
| **Set** | `CARE_LIFECYCLE_SEND=true` (ENABLED must stay true) |
| **Ladder** | |
| | 1) `send --mode=write --limit=10` — review Care Audit sent/failed |
| | 2) `send --mode=write --limit=50` — review again |
| | 3) uncapped cron/CLI — steady send |
| **Success** | Failed rate acceptable; no wrong-recipient reports; idempotency prevents duplicates |
| **Rollback** | See `docs/M9.1_ROLLBACK_CARD.md` — SEND off first |

---

## Phase 4 — Steady state

Follow `docs/M9.1_OPERATIONS_CADENCE.md`.

- Weekly review of skips / sent / failed  
- Monthly volume + consent/copy check  
- Incident: rollback first  

Ownership remains: Case = ops SSOT; Customer = identity; Care = eligibility + Care Audit.
