# M8.2 — Customer Mapping Specification

**Status:** Architecture design (not implemented)  
**Rule:** Exact match only after normalization. No fuzzy matching. Names never auto-merge.

---

## Case → Customer field map

```text
(generated)
  ↓
customer.customerId          # cust_… business id (immutable)

case.notionId
  ↓
case.Customer Page ID        # persistence link (additive Case prop)
case.Customer ID             # mirror of customer.customerId

case.name / Full Name
  ↓
customer.displayName

case.phone / Phone
  ↓
customer.phone               # store normalizePhone(case.phone) when valid

case.email / Email
  ↓
customer.email               # store normalizeEmail(case.email)

case.address / Address
  ↓
customer.primaryAddress

case.line.userId / LINE User ID
  ↓
customer.lineUserId          # exact trim; strongest identity key

case.line.displayName
  ↓
customer.lineDisplayName

case LINE ID handle (lineId)
  ↓
customer.lineId              # display handle only — NOT platform user id

case.line.linked
  ↓
customer.lineLinked

case.line.linkedAt
  ↓
customer.lineLinkedAt

(derived)
  ↓
customer.status              # active if strong key; else unverified (name-only)

(deterministic)
  ↓
customer.sourceFingerprint   # e.g. backfill:v1|case:{notionId}
                             # or backfill:v1|key:{line|phone|email}:{value}
```

---

## Explicit non-mapping (Case remains owner)

Do **not** copy into Customer:

- `campaignOffer` / Offer
- Workflow status / timestamps
- Feedback / report tokens & URLs
- Notification status / LINE message id
- Drive folder ids
- Water score / result summary (Lifetime Score left empty in M8.2)
- Consent fields (do not invent)

---

## Normalization

| Field | Rule |
|-------|------|
| Phone | Strip non-digits; TH `0XXXXXXXXX` → `66XXXXXXXXX`; invalid → treat as missing phone |
| Email | trim + lower-case; empty → missing |
| LINE User ID | trim; exact string equality; no rewrite |
| Name | trim only; never used as join key |

---

## Required vs optional for creation

| Class | Fields |
|-------|--------|
| Strong keys (any one → `active`) | LINE User ID, normalized phone, normalized email |
| Soft identity | displayName (name-only → `unverified`, 1 Case : 1 Customer) |
| Optional enrichment | primaryAddress, lineId, lineDisplayName, linked flags |
| Skip Case | no strong key and no non-empty displayName |
