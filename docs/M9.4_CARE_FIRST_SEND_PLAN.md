## Prerequisites

1. Phase 0–2 complete (ENABLED + dry-run gates)  
2. Staging dry-run done if staging exists; else full prod dry-run + Reviewer/On-call  
3. Checkpoint **A** signed (Operator + Reviewer + On-call)  
4. On-call has rollback card open  

Human then sets:

```text
CARE_LIFECYCLE_ENABLED=true
CARE_LIFECYCLE_SEND=true
```

(No script sets these.)

---

## Limit ladder

```text
--limit=10
    ↓  observe ≥ 24h
Checkpoint B (Operator + Reviewer)
    ↓
--limit=50
    ↓  observe ≥ 48h (prefer 72h if uncertain)
Checkpoint C (Operator + Reviewer)
    ↓
uncapped / cron steady-state
```

### Commands

```bash
# 3a
node scripts/run-care-lifecycle.js send --event=reinspection_6mo --mode=write --limit=10

# after Checkpoint B
node scripts/run-care-lifecycle.js send --event=reinspection_6mo --mode=write --limit=50

# after Checkpoint C — uncapped (document cron; single runner)
node scripts/run-care-lifecycle.js send --event=reinspection_6mo --mode=write
```

## Expansion criteria (all required for GO)

| Criterion | Pass |
|-----------|------|
| Failed share | Below fail-pause: not (`failed/(sent+failed) ≥ 0.20` with n≥5) |
| Wrong recipient | **0** open care-spam / wrong-recipient tickets attributable to Care |
| Idempotency | No duplicate customer-facing push for same key |
| Skip mix | Explainable |
| Case boundary | Case `notificationStatus` still independent / healthy |
| Sign-off | Checkpoint B or C signed as applicable |

Any fail-pause trigger → **do not expand**; execute `docs/M9.4_CARE_ROLLBACK_CARD.md` (SEND off) and investigate.

---

## Fail-pause (locked)

```text
if (sent + failed) >= 5 AND failed / (sent + failed) >= 0.20
  → pause expansion
  → CARE_LIFECYCLE_SEND=false
  → investigate LINE / template / Care Audit
```
