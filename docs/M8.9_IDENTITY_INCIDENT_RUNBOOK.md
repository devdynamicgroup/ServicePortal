# M8.9 — Identity Incident Runbook

**Status:** Active  
**Runtime impact:** Flag changes only via env (human) — this doc does not change code  
**Rollback source of truth:** [`docs/M8.8_ROLLBACK_CARD.md`](./M8.8_ROLLBACK_CARD.md)

---

## Principles

1. **Rollback first, investigate second**  
2. Prefer **Case path** restoration via flags  
3. Preserve audit/logs for forensics  
4. Never “fix” identity under pressure with fuzzy merge or mass data rewrite  

---

## Incident flow (standard)

```text
1. Detect issue
2. Disable affected Customer read flag(s)  ← use M8.8_ROLLBACK_CARD.md
3. Return to Case path (automatic when flags OFF)
4. Preserve audit / logs / reconcile reports
5. Investigate root cause
6. Ticket steward / fix via allow-listed repair or manual merge
7. Re-enter M8.8 phase only after gates green
```

---

## Incident classes

| Class | Symptoms | Minimum rollback |
|-------|----------|------------------|
| Wrong recipient (notify) | Customer got another person’s result | `READ_NOTIFY` (+ shadow) OFF |
| OA history wrong / conflict spike | Wrong or missing history vs Case | `READ_LINE` (+ shadow) OFF |
| Dual-write storm | Create/link errors; Case blocked (should not happen) | `DUAL_WRITE` OFF; verify Case path |
| Orphan / diverge spike | Reconcile gates fail | Do **not** auto-repair diverge; ticket; reads may stay as-is if Case fallback healthy |
| Customers DB down | Lookup errors while reads ON | Read flags OFF; ENABLED OFF if needed |

Always follow the **exact flag order** in `docs/M8.8_ROLLBACK_CARD.md`.

---

## After rollback — verify

```bash
node scripts/check-customer-rollout-gates.js
node scripts/run-customer-reconcile.js status
```

- [ ] Flags match intended safe state  
- [ ] LINE OA history/latest works (Case)  
- [ ] Result send works (Case `line.userId`)  
- [ ] Case create / linkLineUser works  
- [ ] Logs / reports preserved (do not delete `tmp/customer-reconcile` mid-incident)  

---

## Investigate (after stable)

1. Reconcile scan — orphans, diverge, missing links  
2. Merge detect — duplicate LINE/phone/email clusters  
3. LINE / notify metrics and `[customer_line_read]` / `[customer_notify_read]` / `[line_close_notify]`  
4. Dual-write statuses on recent Cases  
5. Escalate `line_diverge` / merges to **identity steward**  

Allow-listed repairs only after dry-run and calm state (see M8.7).

---

## Explicitly forbidden in incident response

- Customer **deletion**  
- **Mass unlink** of Case ↔ Customer  
- **Case rewrite** of Offer / Workflow / Feedback / Report / notification **state**  
- **Emergency fuzzy merge** or name-based merge  
- Overwriting Case LINE on diverge “to make metrics green”  
- Removing Case LINE fields  

---

## Escalation

| Level | Who | When |
|-------|-----|------|
| L1 | On-call | Execute rollback; confirm Case path |
| L2 | Operator + Reviewer | Gates, metrics, phase decision |
| L3 | Identity steward | Merge / diverge identity decisions |
