# M8.9 — M8 Program Completion Criteria

## What “M8 complete” means

The Customer Domain **M8 program** is complete when architecture and operations are documented and tooling exists — not when every production flag is ON.

### Required (met by M8.1–M8.9)

| Criterion | Evidence |
|-----------|----------|
| Identity model documented | Architecture guide + Customer domain docs |
| Ownership boundaries documented | `docs/M8.9_IDENTITY_GOVERNANCE.md` |
| Rollback documented | `docs/M8.8_ROLLBACK_CARD.md` + incident runbook |
| Governance exists | M8.9 cadence + RACI + runbooks |
| Dual-write / merge / reads / reconcile tooling exists | M8.3–M8.7 |
| Rollout ops package exists | M8.8 runbook / checklist / gates |

### Explicitly NOT required

| Not required | Why |
|--------------|-----|
| All `CUSTOMER_DOMAIN_*` flags enabled | Enablement is optional ops via M8.8 |
| Customer primary reads active in production | May remain Case-primary indefinitely |
| Case LINE removed | Forbidden without new ADR; retained permanently under M8.9 |
| Business data migration beyond identity link | Ops stay on Case |
| Auto-merge | Never part of M8 |

---

## Two completion levels

### Architecturally complete (M8.9 docs landed)

- Model, ownership, tooling, rollout, governance documented  
- **Flags may remain OFF**  

### Operationally complete (optional future)

- Conscious decision: Case-primary forever **or** M8.8 Phase 6 done  
- Weekly reconcile green for agreed consecutive weeks  
- Still **does not** authorize Case LINE deletion

## After M8

Next product/architecture work is **M9.0+** under a new plan — not implied by this checklist.  
M8.9 does not start M9.0.
