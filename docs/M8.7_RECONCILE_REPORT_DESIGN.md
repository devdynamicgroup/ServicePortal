# M8.7 — Reconciliation Report Design

**Status:** Implemented (report format used by reconcile CLI)

---

## Metadata

| Field | Description |
|-------|-------------|
| `runId` | Unique reconcile run id |
| `mode` | `dry-run` \| `write` (repairs only) |
| `startedAt` / `finishedAt` | ISO timestamps |
| `flagsSnapshot` | All Customer Domain flags at run start |
| `counts` | Cases scanned, Customers scanned |

---

## Finding counters

| Counter | Meaning |
|---------|---------|
| `missingCustomerLink` | Case needs Customer link |
| `orphanCustomerLink` | Case points at missing/merged Customer |
| `lineDiverge` | Case LINE ≠ Customer LINE (both set) |
| `lineCaseOnly` | Case has LINE; Customer empty |
| `lineCustomerOnly` | Customer has LINE; Case empty |
| `softPhoneConflict` | Linked; phone normalize diverge |
| `softEmailConflict` | Linked; email normalize diverge |
| `unlinkedDuplicateLine` | Informational Case clusters |
| `repairsProposed` | Dry-run repair candidates |
| `repairsApplied` | Write-mode successes |
| `repairErrors` | Write failures |

---

## Finding sample (PII-safe shared logs)

Store full ids in secured report files only. Shared logs: redact LINE / phone / email.

## Pass / fail (suggested staging)

| Gate | Pass |
|------|------|
| Orphan links | 0 |
| Unexplained LINE diverge | 0 (or all have ops tickets) |
| Missing link rate (Cases with LINE) | &lt; 2% |
| Repair write without dry-run report | Fail closed |
