## Governance rules

### CDR required for

| Change type | Examples |
|-------------|---------|
| Template version | Copy text, `templateVersion` bump |
| Timing | `CARE_REINSPECTION_DAYS`, observation/rebook window doc changes |
| Throttle | Cron frequency, default `--limit=` ladder guidance |
| Eligibility rule | Skip reasons, eligibility constants / code thresholds |

### CDR not required for

| Activity | Notes |
|----------|--------|
| Report generation | `run-care-outcome-report.js` |
| Audit viewing | Reading `events.jsonl` / reports |
| Incident rollback | `docs/M9.1_ROLLBACK_CARD.md` first; CDR optional follow-up |
| Fixture / governance tests | Local only |

---

## CDR schema (to land in docs)

Minimum fields (locked for implement):

| Field | Purpose |
|-------|---------|
| `id` | e.g. `CDR-YYYYMMDD-##` |
| `date` / `author` / `reviewer` | Accountability |
| `metricSnapshot` | sent, failed, skip mix, rebookRate, sample size, report path |
| `finding` | What looks wrong or improvable |
| `decision` | `no_change` \| `template` \| `timing` \| `throttle` \| `eligibility` \| `pause_send` |
| `changeDetail` | Before → after (env/key/version) |
| `rollback` | How to undo |
| `followUp` | Next dry-run / success criteria / due date |
| `status` | `draft` \| `approved` \| `applied` \| `reverted` |

CDR files live **outside** Care audit storage. Never append CDRs into `events.jsonl`.

## Optional pattern scanner (read-only)

`scripts/check-care-patterns.js` (design for implement):

```text
Inputs:  tmp/care-lifecycle/latest.json + latest-outcome-report.json (if present)
Output:  warnings only (JSON / console)
Never:   set env, send LINE, rewrite audits, apply policy
```

Suggested patterns (thresholds documented in runbook; conservative defaults):

| Pattern | Hint |
|---------|------|
| High `failed` share | LINE / template health |
| High unexplained skip spike | Eligibility / data shift |
| Eligible volume jump vs prior run | Hold and sample |
| Boundary check stub | Confirm script does not touch Case notification APIs |

Scanner is **advisory**. It does not create CDRs automatically.

## Runtime flows

### Weekly review

```text
node scripts/run-care-outcome-report.js
node scripts/check-care-patterns.js          # optional
→ follow docs/M9.3_CARE_REVIEW_RUNBOOK.md
→ if change proposed: draft CDR → reviewer approve
→ apply only after approval; validate with dry-run (M9.1)
```

### Policy change

```text
docs/M9.3_POLICY_CHANGE_PROCESS.md
  → CDR required?
  → yes: approve → apply → follow-up dry-run
  → no: proceed (report / view / rollback)
```

### Incident

```text
M9.1 rollback card first
→ optional post-incident CDR
→ never mutate historical CareAuditEvent rows
```
