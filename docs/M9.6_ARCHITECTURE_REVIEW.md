Ranked for architectural fit. **None are authorized by this review alone.**

| Item | Notes |

### B. Outcome signal deepening (Care-owned)

| Candidate | Description | Prerequisite |
|-----------|-------------|--------------|
| B1. CareOutcomeEvent store (M9.2 Option B) | Separate outcome rows keyed by careAuditId | Volume/history pain on Option A |

| B3. Narrow `care_*` LINE postbacks | Ack / book / opt-out signals | OA intent priority below M7 feedback; webhook design |

### C. Second Care event type (policy expansion)

| Candidate | Description | Prerequisite |
|-----------|-------------|--------------|
| C1. New event (e.g. post-service tip / filter cadence) | Same engine, new eligibility + template + idempotency key | Stable SEND + CDR history + reused M9.1/M9.4 gates |
| C2. Multi-event scheduler | Shared cron evaluating multiple event types | C1 proven; single-runner still mandatory |

**Governance:** New event = **new campaign-class change** → CDR + go/no-go equivalent to M9.4 (not a silent template tweak).

### D. Ops visibility (Care-owned metrics UX)

| D2. Durable audit in Notion/DB | Beyond file `tmp/` for prod forensics | Optional; file audit remains valid |

### E. Explicitly deferred / poor M9.6 fit

## 2. Ownership boundaries

| Concern | Owner in any M9.6 evolution |
|---------|------------------------------|
| New Care event definition | **Care** (+ CDR + Reviewer) |
| Eligibility / template / throttle | **Care** (CDR-gated) |
| Care Audit / outcomes | **Care** |
| Result-send lifecycle | **Case** — untouched |
| Identity / consent truth | **Customer** — Care reads; no fuzzy expansion |
| LINE OA intent priority | Existing OA owners; Care postbacks must not preempt feedback |
| Booking CTA / UTM | Care proposes; booking/Framer owners accept contract |

**No ownership movement** Case ↔ Customer ↔ Care.

## 3. Operational risks

| Risk | Mitigation |
|------|------------|
| Evolving Care before first SEND | Prefer M9.4 launch first; M9.6 plan gated on live (or staging SEND) evidence |
| Second event without gate reuse | Mandate M9.4-style dry-run + limit ladder per event type |
| Postback collisions with M7 | `care_*` prefix; priority below feedback tokens |
| Option B premature complexity | Stay Option A until audit history/reporting pain is real |
| Dashboard that edits Case fields | Forbid; Care aggregates only |
| Scope as marketing platform | Non-goals below |
| Auto decisions sneaking in | Explicit forbid; human CDR / go-no-go only |
