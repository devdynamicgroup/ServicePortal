# M9.5 — Care Metrics Ownership

**Status:** Active (governance)  
**Related:** `docs/M9.5_CARE_STEADY_STATE_HANDBOOK.md` · `docs/M9.2_OUTCOME_SCHEMA.md` · `docs/M9.5_CARE_INCIDENT_OPERATIONS.md`

---

## Principles

- Care owns Care delivery and outcome metrics.  
- Case owns result-send health (separate).  
- Customer steward owns consent identity facts — not Care KPI dashboards.  
- Exact join only for rebook attribution (no fuzzy / name).  

---

## Delivery metrics

| Metric | Definition / source | Owner | Escalate to |
|--------|---------------------|-------|-------------|
| sent | Care Audit / run `latest.json` | Operator | — |
| failed | Care Audit / LINE errors | Operator | **On-call** if fail-pause or spike |
| skipped | Run report + reason codes | Operator | Reviewer if unexplained mass skips |
| Duplicate prevention | Idempotency index / `already_sent` | Operator | On-call if double-send suspected |

### Fail-pause (from M9.4)

```text
failed / (sent + failed) ≥ 0.20  AND  (sent + failed) ≥ 5
  → pause SEND (rollback card) → On-call + Operator
```

---

## Outcome metrics

| Metric | Definition / source | Owner | Escalate to |
|--------|---------------------|-------|-------------|
| response mix | Outcome report (`unknown` / `no_response` / `utm_click` / `rebooked` / `opted_out`) | Operator drafts; Reviewer interprets | — |
| rebook within window | M9.2: exact customerId/LINE within 30d | Care domain; Reviewer on effectiveness | Steward if join/identity doubt |
| opt-out / consent skips | `consent_line_false` + Customer consent | Operator + Identity steward | Reviewer if Care sent despite consent false |
| complaints | Support / OA tickets about Care | On-call (first response) | Operator forensics; Reviewer for re-entry |

---

## Governance metrics

| Artifact | Owner | Escalate to |
|----------|-------|-------------|
| CDR history / backlog | Operator maintains | Reviewer for stalled `approved` not applied |
| Policy changes applied | Operator | Reviewer if change lacked CDR |
| Approvals | Reviewer | On-call for incident-class decisions |

---

## Escalation paths (summary)

```text
Delivery spike / fail-pause / wrong recipient
  → On-call: SEND=false (then ENABLED if needed)
  → Operator: preserve audits
  → Reviewer: re-entry only via checklist

Consent / identity edge
  → Identity steward
  → Do not fuzzy-fix

Policy improvement
  → Operator CDR draft
  → Reviewer approve
  → Not an incident path
```

---

## What Case / Customer do not own

| Domain | Not responsible for |
|--------|---------------------|
| Case owners | Care sent/failed KPIs, CDR approvals |
| Customer stewards | Care campaign ROI; they own consent truth only |
