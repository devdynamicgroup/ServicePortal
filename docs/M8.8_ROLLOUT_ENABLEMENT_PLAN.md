# M8.8 — Customer Read Rollout & Production Enablement Plan

**Status:** Ops package complete — human-gated enablement; **flags remain default OFF**  
**Mode:** Rollout operations (runbook / checklist / rollback); no auto-enable  
**Out of scope:** New identity model; auto-merge; Case ownership migration; removing Case LINE fields; M8.9

Ops docs: `docs/M8.8_PHASE_RUNBOOK.md` · `docs/M8.8_GO_NO_GO_CHECKLIST.md` · `docs/M8.8_ROLLBACK_CARD.md`  
Gate script (read-only): `node scripts/check-customer-rollout-gates.js`

---

## Goal

Controlled production activation of Customer identity **reads** already implemented in M8.5–M8.6, using M8.7 reconcile gates and flag-only rollback.

M8.8 is an **operations + readiness** milestone, not a domain redesign.

---

## Fixed sequence (never skip forward)

```text
Phase 0  all OFF
Phase 1  ENABLED
Phase 2  DUAL_WRITE
Phase 3  READ_LINE_SHADOW
Phase 4  READ_LINE
Phase 5  READ_NOTIFY_SHADOW
Phase 6  READ_NOTIFY
```

All flags remain **default false** in code/config templates. Production values are set only by operators after gates pass.

`MERGE_ENABLED` stays independent and **OFF** unless a separate merge ops ticket requires it. M8.8 does not require merge execute.

---

## 1. Production readiness gates (pre–Phase 3)

Run before enabling any read shadow/primary in production:

| Gate | Tool | Pass criteria (staging → prod) |
|------|------|--------------------------------|
| Schema / DB | Customers DB configured; Case link props present | `NOTION_CUSTOMERS_DATABASE_ID` set; Case `Customer ID` / `Page ID` exist |
| Reconcile scan | `run-customer-reconcile.js scan` | `gateResult.passed === true` |
| Orphan links | reconcile counters | `orphanCustomerLink = 0` unexplained |
| LINE diverge | reconcile | `lineDiverge = 0` **or** every finding ticketed with owner + no auto-repair |
| Missing links (LINE Cases) | reconcile | rate ≤ **2%** of Cases with LINE (`missingCustomerLinkAmongLineLinkedMaxRate`) |
| Duplicate Customers | `run-customer-merge.js detect` | 0 unexplained LINE/phone/email clusters **or** all queued as manual tickets |
| Soft phone/email conflicts | reconcile | Informational; no block unless ops policy tightens |
| Dual-write health (after Phase 2) | logs / dual-write status | Case create + LINE link never blocked; dual-write errors trending down |
| No fuzzy / auto-merge | policy | Confirmed OFF |

**Staging must complete Phases 1–6 successfully** before production Phase 3+.

## 2. Rollout phases

### Phase 0 — Baseline (all OFF)

| | |
|--|--|
| Flags | All Customer Domain flags `false` |
| Behavior | Case-only LINE OA + Case-only notify destination (today) |
| Success | Baseline: reconcile scan report archived; fixture tests green; health shows flags OFF |
| Monitor | Reconcile counters; LINE/notify error rates (Case path) |
| Rollback | N/A |

### Phase 1 — `CUSTOMER_DOMAIN_ENABLED=true`

| | |
|--|--|
| Behavior | Master switch ON; **no** dual-write / reads unless other flags on → still Case-primary ops |
| Success | App healthy; Customers DB check `ready`; no unexpected Customer calls on hot paths |
| Monitor | Config warnings; `/ops` customerDomain flags; error rate |
| Rollback trigger | Startup instability; Customers DB missing → set ENABLED=false |
| Hold | ≥ **24h** staging; ≥ **24h** prod soak recommended |

### Phase 2 — `CUSTOMER_DOMAIN_DUAL_WRITE=true`

| | |
|--|--|
| Requires | ENABLED |
| Behavior | createCase + linkLineUser dual-write; Case success never blocked |
| Success | Dual-write success rate ≥ **99%** over soak; zero Case create regressions; new Cases get Customer links |
| Monitor | Dual-write status codes; reconcile `missingCustomerLink` trend down on new Cases |
| Rollback trigger | Dual-write error spike; Case create/link failures → DUAL_WRITE=false (ENABLED may stay) |
| Hold | ≥ **48h** staging; ≥ **72h** prod recommended before Phase 3 |

### Phase 3 — `CUSTOMER_DOMAIN_READ_LINE_SHADOW=true`

| | |
|--|--|
| Requires | ENABLED; DUAL_WRITE strongly recommended ON |
| Behavior | OA history/latest: **Case reply**; Customer path compare + metrics |
| Success | ≥ **200** lookups (or ≥ **7 days** if volume low); mismatch rate &lt; **1%**; unexplained conflicts = **0** |
| Monitor | `lineReadMetrics`: hits, misses, mismatches, conflicts, errors |
| Rollback trigger | Mismatch ≥ 1%; conflicts &gt; 0 unexplained; OA reply errors → SHADOW=false |
| Hold | Meet volume **or** time gate, whichever first with min **48h** |

### Phase 4 — `CUSTOMER_DOMAIN_READ_LINE=true` (SHADOW off or ignored)

| | |
|--|--|
| Requires | Phase 3 gates passed |
| Behavior | Customer → Cases primary; **Case LINE fallback** always |
| Success | Fallback rate explained; mismatch after fallback &lt; **0.5%**; UX parity on view_latest/history |
| Monitor | Same LINE metrics; customer care complaints |
| Rollback trigger | History incomplete vs Case path; conflict spike → READ_LINE=false (instant Case-only) |
| Hold | ≥ **72h** before Phase 5 |

### Phase 5 — `CUSTOMER_DOMAIN_READ_NOTIFY_SHADOW=true`

| | |
|--|--|
| Requires | ENABLED; DUAL_WRITE ON; Phase 4 stable (or explicit waiver) |
| Behavior | Push still **Case LINE**; Customer LINE compared |
| Success | ≥ **100** notify resolves (or ≥ **7 days**); unexplained mismatch &lt; **1%**; **0** wrong-recipient incidents |
| Monitor | `notifyReadMetrics`: mismatches, caseFallback, errors; LINE send failure rate unchanged |
| Rollback trigger | Mismatch ≥ 1%; any wrong-recipient → SHADOW=false |
| Hold | Volume **or** time; min **48h** |

### Phase 6 — `CUSTOMER_DOMAIN_READ_NOTIFY=true`

| | |
|--|--|
| Requires | Phase 5 gates passed |
| Behavior | Customer destination when safe; **Case wins on LINE diverge**; Case fallback on miss/error |
| Success | Send success rate ≥ baseline; diverge handled as Case; payload unchanged |
| Monitor | Notify metrics; notification `failed` rate; closeCase/send APIs |
| Rollback trigger | Send failure spike; suspected wrong recipient → READ_NOTIFY=false immediately |
| Hold | Ongoing; Case LINE fields **retained indefinitely** |

## 3. Monitoring (ops checklist)

### Identity / reconcile

- `orphanCustomerLink`, `lineDiverge`, `missingCustomerLink`, soft conflicts  
- Merge detect cluster count (manual)  
- Dual-write inactive vs success/error  

### LINE (M8.5)

- `totalLookups`, `customerHits`, `customerMisses`, `caseFallbacks`, `casePrimaryHits`  
- `mismatches`, `conflicts`, `missingLinks`, `errors`  
- Dump: `node scripts/dump-customer-line-read-metrics.js` / ops health snapshot  

### Notify (M8.6)

- `notifyResolves`, `customerHits`, `customerNoLine`, `caseFallbacks`  
- `mismatches`, `errors`, `skippedNoLine`  
- Case notification status `failed` / `sent` rates (lifecycle still Case)  

### Process note

In-process metrics reset on deploy/restart — pair with log aggregation (`[customer_line_read]`, `[customer_notify_read]`, `[line_close_notify]`) for durable observation windows.

---

## 4. Safety rules (non-negotiable)

- Case = operational SSOT (Booking, Workflow, Offer, Feedback, Report, Notification **state**)  
- Customer = identity only  
- No automatic merge; no fuzzy/name matching  
- No destructive repair; `line_diverge` report-only  
- Case LINE fields retained (fallback + safety)  
- No HTTP repair apply  
- Flag changes only via env/deploy — not application “auto promote”  

---

## 5. Rollback (flag-only)

Immediate, in **reverse dependency order** as needed:

```text
CUSTOMER_DOMAIN_READ_NOTIFY=false
CUSTOMER_DOMAIN_READ_NOTIFY_SHADOW=false
CUSTOMER_DOMAIN_READ_LINE=false
CUSTOMER_DOMAIN_READ_LINE_SHADOW=false
# optional if write path unstable:
CUSTOMER_DOMAIN_DUAL_WRITE=false
CUSTOMER_DOMAIN_ENABLED=false
```

**Never required for rollback:** customer deletion, mass unlink, reverse migration, Case data rewrite.

Data written while dual-write was ON may remain (additive). Safe.
