**Status:** Implemented (CARE flags default OFF; no M9.1 runtime changes)  
**Mode:** Runtime module + CLI landed — production enablement human-gated via **M9.1 ops package**  
**Architecture:** `docs/M9.0_ARCHITECTURE_REVIEW.md`  
**Operations:** `docs/M9.1_CARE_RUNBOOK.md` · `docs/M9.1_GO_NO_GO_CHECKLIST.md` · `docs/M9.1_ROLLBACK_CARD.md`  
**Initial event:** `care.reinspection_6mo` (6-month re-inspection reminder)

---

## Goal

Define the implementation boundary for a **Care Lifecycle Event** layer that:

- Derives eligibility from **Case** history  
- Keeps Case as operational SSOT  
- Keeps Customer as identity only  
- Uses a **separate Care Audit** lifecycle (never Case `notificationStatus`)  
- Supports **dry-run before any send**  

No runtime code in this step.

---

## Locked architecture decisions

### Ownership

| Owner | Owns |
|-------|------|
| **Case** | Service timing; inspection/result history; **result** notification state |
| **Customer** | Identity; LINE projection |
| **Care module** | Event evaluation; eligibility policy; template selection; **care audit** lifecycle |

### Storage

**Separate Care Audit storage.** Do **not** store reminder state in Case notification fields or alter the Case result-send state machine.

#### `CareAuditEvent` schema (locked)

```text
CareAuditEvent
  id
  caseId
  customerId
  eventType
  scheduledAt
  triggerSource
  destinationType          # case_line | customer_line
  destinationIdHash        # PII-safe hash of LINE user id
  status                   # planned | dry_run | skipped | sending | sent | failed
  idempotencyKey
  templateVersion
  createdAt
  sentAt
  failureReason
```

#### Persistence choice (locked for M9.0 implement)

| Option | Decision |
|--------|----------|
| Notion **Care Audits** DB (new) | **Primary** for durable ops visibility |
| Local `tmp/care-lifecycle/` JSON reports | Always for dry-run CLI output |
| Case notification properties | **Forbidden** |

Env (future): `NOTION_CARE_AUDITS_DATABASE_ID` — optional while flags OFF / dry-run file-only mode allowed.

### Destination

| Mode | Behavior |
|------|----------|
| Default / Customer `READ_NOTIFY` OFF | `Case.line.userId` |
| `READ_NOTIFY` ON | Reuse M8.6 notify-reader policy (Case wins on diverge) |
| No LINE | `skipped` audit; no send |

Care module **must not** invent LINE via phone/email/name.

### Feature flags (defaults OFF)

```text
CARE_LIFECYCLE_ENABLED=false   # master: evaluate + dry-run allowed
CARE_LIFECYCLE_SEND=false      # actual LINE push (requires ENABLED)
```

Independent of `CUSTOMER_DOMAIN_*`. Never auto-enable Customer flags.

### Idempotency (locked)

```text
idempotencyKey = care:reinspection_6mo:{caseNotionId}:{periodBucket}
periodBucket   = YYYY-MM of eligibility anchor + 6 months (UTC)
```

Same key → no duplicate send; dry-run may upsert `dry_run` / `planned` without sending.

### Eligibility (6-month reminder)

Anchor (first available):

1. `Case.notification.resultSentAt`  
2. else `Case.workflow.serviceCompletedAt`  
3. else skip (no anchor)

Eligible when:

- Anchor ≥ ~182 days ago (configurable `CARE_REINSPECTION_DAYS`, default **182**)  
- Case has resolvable LINE (or dry-run still records `skipped` reason)  
- No existing CareAuditEvent with same `idempotencyKey` in `sent` / `sending`  
- Optional: if Customer linked and `consentLine === false` → `skipped` (consent gate)  

Not eligible solely by Customer without Case history.

### Scheduler (locked for M9.0)

**Offline CLI + external cron** (Render cron / OS scheduler).  
No always-on in-process scheduler in first implement (avoids double-fire on multi-instance).

```bash
node scripts/run-care-lifecycle.js scan --event=reinspection_6mo --mode=dry-run
node scripts/run-care-lifecycle.js send --event=reinspection_6mo --mode=write   # requires SEND flag
```

### Consent (locked)

- If Case has Customer link and Customer has explicit `consentLine === false` → skip send  
- If consent unknown / no Customer → allow Case LINE path (care, not marketing); copy must remain care-tone

## Runtime flows

### Dry-run (`ENABLED` optional for local fixtures; prod: ENABLED=true, SEND=false)

```text
load Cases (limit)
  → for each: eligibility.reinspection_6mo
  → resolve destination (no send)
  → write CareAuditEvent status=dry_run|skipped + file report
```

### Send (`ENABLED` + `SEND`)

```text
same as dry-run candidates
  → idempotency check (skip if sent)
  → status=sending → LINE push → sent|failed
  → never update Case.notificationStatus
```

## Testing plan (for future implement)

| # | Scenario | Expect |
|---|----------|--------|
| 1 | Flags OFF | CLI no-op or refuse send; no LINE calls |
| 2 | Dry-run eligible Case | Audit `dry_run`; no LINE; Case notification untouched |
| 3 | Anchor missing | `skipped` |
| 4 | Duplicate idempotency | Second run no second send |
| 5 | SEND without ENABLED | Config warn / refuse |
| 6 | Customer consentLine false | `skipped` |
| 7 | READ_NOTIFY OFF | destinationType `case_line` |
| 8 | Case notificationStatus unchanged after care send | Assert |

## Rollback

1. `CARE_LIFECYCLE_SEND=false` → stop pushes  
2. `CARE_LIFECYCLE_ENABLED=false` → stop evaluation in prod cron  
3. No Case/Customer data rollback  
4. Care audit rows retained for forensics  

---

## Regression risks

| Risk | Mitigation |
|------|------------|
| Care send flips result-sent | Separate audit; tests forbid Case notification writes |
| Double reminder | Idempotency key + status check |
| Depends on Customer flags | Case LINE default path |
| Spam | Days threshold; consent skip; care copy only |
