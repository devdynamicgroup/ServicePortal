## Purpose

How Care Decision Records operate in **steady state**: propose → approve → apply → review.

CDRs stay **separate** from CareAuditEvent. Historical audits remain **immutable**.

---

## CDR lifecycle

```text
draft
  → approved   (Reviewer named)
  → applied    (Operator executed changeDetail)
  → reverted   (optional; rollback section used)
```

| Status | Rule |
|--------|------|
| draft | Operator may edit freely |
| approved | Requires named Reviewer; required before apply for policy changes |
| applied | Only after approved; date the apply |
| reverted | Record how rollback was done |

Scripts must **never** auto-create or auto-approve CDRs.

---

## When to propose

From weekly classification (`docs/M9.3_POLICY_REVIEW_RUNBOOK.md`):

| Class | CDR? |
|-------|------|
| healthy | Optional `no_change` or skip |
| investigate | No policy CDR yet |
| propose_change | **Required** before timing/copy/throttle/eligibility change |

### CDR required

- Template / copy  
- Timing  
- Throttle  
- Eligibility  

### CDR not required

- Report generation  
- Audit viewing  
- Incident flag rollback (optional post-incident CDR after stability)  

---

## Cadence (locked)

| Cadence | Action |
|---------|--------|
| **Weekly** | Classify effectiveness; draft CDR if `propose_change` |
| **Monthly** | Review open CDRs (`approved` not applied; `applied` follow-ups due) |
| **Same lever** | Prefer ≥ **7 days** between successive **applied** CDRs on the same lever (timing / template / throttle / eligibility), unless incident-driven |
| **One lever** | Prefer one material change per CDR |

---

## Approval process

1. Operator drafts CDR with `metricSnapshot` + `finding` + `changeDetail` + `rollback` + `followUp`  
2. Reviewer signs → `status=approved`  
3. Operator applies **only** `changeDetail`  
4. Mark `applied`; run dry-run / observe per follow-up  
5. Implementation review: did success criteria pass? If not → `reverted` or new CDR  

**Human approval is mandatory.** No auto-tuning.

---

## Implementation review (after apply)

- [ ] Change matches CDR `changeDetail`  
- [ ] Dry-run or live observe completed per `followUp`  
- [ ] No Case `notificationStatus` side effects  
- [ ] SEND not enabled as a side effect of the CDR  
- [ ] Same-lever spacing respected (or incident exception noted)
