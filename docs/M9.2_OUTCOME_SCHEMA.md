# M9.2 — Care Outcome Schema

**Status:** Implemented (additive on CareAuditEvent)  
**Never** map onto Case `Notification Status` / `Result Sent At`.

---

## Fields

| Field | Type | Meaning |
|-------|------|---------|
| `deliveryStatus` | string | Mirror of audit `status` |
| `responseStatus` | string | `unknown` \| `no_response` \| `utm_click` \| `rebooked` \| `opted_out` |
| `rebookWithin30d` | boolean | Later Case attributed within 30 days |
| `utmSource` | string\|null | From booking URL |
| `utmCampaign` | string\|null | From booking URL |
| `careAuditIdFromUtm` | string\|null | `care_audit_id` query param |
| `linkedCaseIdAfter` | string\|null | Attributed rebook Case notion id |
| `outcomeAt` | ISO\|null | When outcome observed |
| `outcomeSource` | string\|null | `derived_rebook` \| `booking_utm` \| … |
| `observationWindowEndsAt` | ISO\|null | `sentAt` + 7 days |
| `measuredAt` | ISO\|null | Measurement timestamp |

---

## Windows

| Window | Days |
|--------|------|
| Response / `no_response` | 7 |
| Rebook attribution | 30 |

Rebook join: exact `customerId` **or** exact LINE User ID only.

---

## Report CLI

```bash
node scripts/run-care-outcome-report.js
node scripts/run-care-outcome-report.js --with-cases
node scripts/test-care-outcomes.js
```

Flags (default OFF): `CARE_OUTCOME_TRACKING`, `CARE_OUTCOME_REPORT`  
`CARE_LIFECYCLE_SEND` remains independent and default OFF.
