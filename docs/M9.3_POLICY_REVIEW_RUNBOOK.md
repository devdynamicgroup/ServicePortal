# M9.3 — Care Policy Review Runbook

**Status:** Active (governance)  
**Related:** `docs/M9.3_CARE_DECISION_RECORDS.md` · `docs/M9.3_EFFECTIVENESS_GOVERNANCE.md` · `docs/M9.1_OPERATIONS_CADENCE.md` · `docs/M9.4_CARE_PRODUCTION_RUNBOOK.md`

---

## Purpose

Weekly and monthly **human review** of Care effectiveness using M9.2 outcome reports and M9.1 run archives.

```text
Collect signals → Classify → CDR if change → Approve → Apply → Dry-run validate
```

---

```bash
node scripts/check-care-rollout-gates.js
node scripts/run-care-outcome-report.js
node scripts/check-care-patterns.js
```

| Artifact | Path / command |
|----------|----------------|

| Outcome report | `tmp/care-lifecycle/latest-outcome-report.json` |

## Weekly review

1. **Flags** — Confirm intended phase; `CARE_LIFECYCLE_SEND` only via M9.1 go/no-go (not this runbook).  
2. **Run health** — Review `latest.json` counts: dry_run / sent / skipped / failed.  
3. **Outcomes** — Review delivery + response mix + `rebookRate` (may be n/a while SEND off).  
4. **Patterns** — Read scanner warnings; do not treat as auto-tickets.  
5. **Classify**

| Class | Meaning | Next |
|-------|---------|------|
| `healthy` | Explained mix; no action | Optional `no_change` CDR or skip CDR |
| `investigate` | Unclear spike / sample issue | Dig into audits; no policy change yet |
| `propose_change` | Template / timing / throttle / eligibility | Draft CDR → reviewer |

6. **Case boundary** — Confirm Case result-send health unchanged; Care did not write `notificationStatus`.  
7. **Archive** — Keep report paths in CDR `metricSnapshot` when filing.

### Weekly checklist

- [ ] Gate script reviewed  
- [ ] Outcome report generated / opened  
- [ ] Pattern scanner reviewed (optional but recommended)  
- [ ] Skip / fail samples spot-checked  
- [ ] Classification recorded (healthy / investigate / propose_change)  
- [ ] CDR drafted if propose_change  
- [ ] No SEND enablement from this review  

---

## Monthly review

- [ ] Eligible volume trend vs Case population  
- [ ] Rebook / response trends (once SEND history exists; else qualitative)  
- [ ] Care copy / Thai tone still appropriate  
- [ ] Consent skip samples (`consent_line_false`)  
- [ ] Confirm no pressure to merge Care into Case notification state  
- [ ] On-call still knows `docs/M9.1_ROLLBACK_CARD.md`  
- [ ] Open CDRs: any `approved` not yet `applied`? any `applied` due for follow-up?  

---

## After an approved CDR

1. Apply **only** the `changeDetail` in the CDR.  
2. Mark CDR `applied` with date.  
3. Run dry-run validation (M9.1):

```bash
node scripts/run-care-lifecycle.js scan --event=reinspection_6mo --mode=dry-run
```

4. Spot-check sample rows against CDR success criteria.  
5. Do **not** enable SEND as a side effect of a timing/template CDR.

---

## Incident path

1. Rollback first — `docs/M9.1_ROLLBACK_CARD.md`  
2. Investigate Care Audit + outcome report  
3. Optional post-incident CDR  
4. Never rewrite historical `events.jsonl` rows  

---

## Advisory thresholds (pattern scanner)

Conservative defaults used by `scripts/check-care-patterns.js` (tune only via CDR if changing guidance):

| Pattern | Default hint threshold |
|---------|------------------------|
| High failed share | `failed / (sent+failed) ≥ 0.20` when denominator ≥ 5 |
| High skip share | `skipped / total ≥ 0.80` when total ≥ 10 |
| Volume jump | eligible/dryRun count ≥ 2× prior `latest` when prior ≥ 5 |
| Missing reports | warn if latest or outcome report absent |

Scanner never mutates env, audits, or flags.
