## Locked rollout sequence

```text
CARE OFF
  → CARE_LIFECYCLE_ENABLED=true
  → dry-run verification
  → approval checkpoint A (production readiness)
  → CARE_LIFECYCLE_SEND=true
  → limit=10
  → observe
  → approval checkpoint B
  → limit=50
  → observe
  → approval checkpoint C
  → uncapped
  → steady state (Phase 4)
```

Never skip dry-run. Never jump to uncapped without **10 then 50**.  
Implementing M9.4 docs does **not** advance any phase.

---

## Locked decisions (architecture §10 resolved)

| # | Decision | Lock |
|---|----------|------|
| 1 | Observation windows | After `--limit=10`: ≥ **24 hours** + Audit review. After `--limit=50`: ≥ **48 hours** (prefer **72h** if volume/complaints uncertain) before uncapped |
| 2 | Staging verification | **If staging exists:** complete Phase 1–2 dry-run gates on staging before prod ENABLED/SEND. **If no staging:** prod dry-run must meet full gates (≥3 scans, ≥7d or ≥14d low volume) with Reviewer + On-call ack — no shortcut |
| 3 | Outcome flags at launch | **Leave OFF** by default. File-based `run-care-outcome-report.js` is enough for launch monitoring. Enabling `CARE_OUTCOME_*` is optional and **independent** of SEND go/no-go |
| 4 | Fail-pause threshold | Align with pattern scanner: **failed / (sent+failed) ≥ 0.20** when denominator ≥ **5** → pause SEND (rollback card) and investigate |
| 5 | Sign-off roles | **Checkpoint A** (first SEND): Operator + Reviewer + On-call. **B / C** (10→50, 50→uncapped): Operator + Reviewer (On-call ack if any incident since prior step) |
| 6 | Auto-set SEND | **Never** — no script, cron, or doc step auto-writes SEND=true |
| 7 | Docs vs tooling | **Docs-first**. Optional read-only `check-care-production-readiness.js` allowed; must never change flags |

## Doc content outline (for implement)

### Production runbook

- Map Phase 0–4 to commands already in M9.1  
- Checkpoints A–C with locked observe windows  
- Monitoring requirements (delivery, fail-pause 20%, skips, duplicates, complaints, outcomes)  
- Steady-state handoff to M9.1 cadence + M9.3 CDR  
- Explicit: this package never sets flags

### Go / no-go checklist

- All §1 readiness gates from architecture (eligibility, dry-run, consent, LINE, idempotency, audit, outcomes)  
- Launch blockers table (wrong anchors, Case notification mutation, unexplained volume jump, etc.)  
- Signature block: Operator / Reviewer / On-call for A; Operator / Reviewer for B/C  

### First-send plan

- Pilot: `care.reinspection_6mo` only; safety via `--limit=`  
- Ladder: 10 → 24h → 50 → 48–72h → uncapped  
- Expansion criteria: failed share below pause threshold; no wrong-recipient; idempotency OK; Reviewer GO  

### Rollback card

```text
1. CARE_LIFECYCLE_SEND=false
2. CARE_LIFECYCLE_ENABLED=false   # if cron/eval must stop
```

Non-actions: no Case rewrite, no Customer rollback, no audit deletion, no identity changes.  
Retain link to `docs/M9.1_ROLLBACK_CARD.md` (canonical emergency card; M9.4 adds prod ladder context).

### Optional readiness script

```text
Inputs: flags + latest.json + latest-outcome-report.json (+ optional prior)
Output: JSON gate summary / warnings
Never: set env, send LINE, apply policy, create CDRs
```
