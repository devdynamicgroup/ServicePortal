# M8.8 — Rollback Card (Flag-Only)

**Emergency use.** Disable Customer identity reads/writes via environment flags.  
**Do not** delete Customers, mass-unlink Cases, reverse-migrate, or rewrite Case ops data.

Related: `docs/M8.8_PHASE_RUNBOOK.md`

---

## Immediate order (stop at the first stable layer)

```text
1. CUSTOMER_DOMAIN_READ_NOTIFY=false
2. CUSTOMER_DOMAIN_READ_NOTIFY_SHADOW=false
3. CUSTOMER_DOMAIN_READ_LINE=false
4. CUSTOMER_DOMAIN_READ_LINE_SHADOW=false
5. CUSTOMER_DOMAIN_DUAL_WRITE=false     # if write path unstable
6. CUSTOMER_DOMAIN_ENABLED=false       # if master switch unstable
```

Redeploy / restart as required by the host so env is loaded.

---

## When to roll back

| Symptom | Minimum action |
|---------|----------------|
| Suspected wrong LINE recipient on push | Steps 1–2 (NOTIFY off) |
| OA history wrong / conflict spike | Steps 3–4 (LINE off) |
| Case create/link blocked or dual-write error storm | Step 5 |
| Customers DB missing / startup instability | Step 6 |
| Full abort to pre-Customer runtime | Steps 1–6 |

---

## After rollback — verify

```bash
node scripts/check-customer-rollout-gates.js
node scripts/run-customer-reconcile.js status
```

Confirm:

- [ ] Flags match intended rollback state
- [ ] LINE OA history/latest works (Case path)
- [ ] Result send works (Case `line.userId`)
- [ ] Case create / linkLineUser works

---

## Explicit non-actions

- Do **not** remove Case `LINE User ID` fields  
- Do **not** run destructive reconcile repairs for diverge  
- Do **not** auto-merge  
- Do **not** change Offer / Workflow / Feedback / Report / notification **state** ownership  

Additive Customer rows / Case Customer ID links created while dual-write was ON may remain. That is safe.
