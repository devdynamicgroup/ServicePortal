# M9.5 — Care Incident Operations

**Status:** Active (governance)  
**Related:** `docs/M9.4_CARE_ROLLBACK_CARD.md` · `docs/M9.1_ROLLBACK_CARD.md` · `docs/M9.5_CARE_METRICS_OWNERSHIP.md` · `docs/M9.5_CARE_STEADY_STATE_HANDBOOK.md`

---

## Purpose

Production (and pre-SEND) incident handling for Care.  
**Rollback is flag-only.** Preserve audits for forensics.

---

## Incident classes

| Class | Examples | First action |
|-------|----------|--------------|
| Delivery failure | Fail-pause ≥20% with n≥5; LINE/token errors | `CARE_LIFECYCLE_SEND=false` |
| Wrong recipient | Care spam / wrong LINE complaint | `SEND=false` immediately |
| Consent issue | Sent despite consent false; consent data bug | `SEND=false` + identity steward |
| Boundary violation | Suspected Case notification mutation by Care | `SEND=false` + `ENABLED=false`; escalate |
| Eval / cron chaos | Double runner; scan instability | `ENABLED=false` if eval must stop |

---

## Response process

```text
1. Detect (metrics, complaint, pattern scanner, readiness)
2. Rollback flags (below)
3. Verify Case result-send + LINE OA still healthy
4. Preserve Care Audit / reports / idempotency index
5. Investigate (Operator)
6. Optional post-incident CDR after stability
7. Re-entry only via M9.4 go/no-go (Reviewer)
```

---

## Rollback flow (flag-only)

```text
1. CARE_LIFECYCLE_SEND=false
2. CARE_LIFECYCLE_ENABLED=false    # if evaluation / cron must stop
```

Redeploy/restart per host.

```bash
node scripts/check-care-rollout-gates.js
node scripts/check-care-production-readiness.js
node scripts/check-care-steady-state.js
```

Canonical cards: `docs/M9.4_CARE_ROLLBACK_CARD.md` · `docs/M9.1_ROLLBACK_CARD.md`

---

## Escalation

| Role | Duty |
|------|------|
| On-call | Execute flag rollback; own customer-facing first response |
| Operator | Stop cron; preserve artifacts; draft facts for CDR |
| Reviewer | Approve any return to SEND; require dry-run as needed |
| Identity steward | Consent / wrong-recipient identity follow-up |

---

## Explicit non-actions

- Do **not** rewrite Case `notificationStatus` / `resultSentAt`  
- Do **not** delete Care Audit or idempotency index mid-incident  
- Do **not** Customer mass-unlink / fuzzy-merge  
- Do **not** auto-re-enable SEND  
- Do **not** treat M9.5 handbook as authority to set SEND=true  

---

## After incident

- Optional CDR (`pause_send` / fix eligibility / template) once stable  
- Weekly review notes the incident class and resolution  
- Same-lever 7-day CDR spacing may be waived when incident-driven — note exception in CDR
